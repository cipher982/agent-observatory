# Agent Observatory 0.3 Safe Capture Spec

## Product Promise

Agent Observatory 0.3 is an install-once macOS app for observing coding-agent LLM traffic. Its strongest guarantee is safety: enabling capture must not break arbitrary developer tools. Full request-body capture is offered for supported, trust-ready clients. Unknown clients are passed through and surfaced as coverage gaps.

This is intentionally narrower than "MITM every HTTPS request from every tool." NetworkExtension can route provider flows, but each client still controls TLS trust. The product should win by being safe, transparent, and excellent for the primary coding agents.

## Current Research Summary

- macOS NetworkExtension exposes per-flow source metadata (`sourceAppSigningIdentifier` and `sourceAppAuditToken`) that can be forwarded to the daemon for capture policy. The signing identifier is a routing signal, not a complete identity proof by itself; pair it with audit-token/PID/env evidence and keep the default conservative. If local process-env evidence is unreadable or missing, treat the flow as not trust-ready and tunnel it.
- Node supports additive custom roots with `NODE_EXTRA_CA_CERTS`; this is process-start behavior, so stale long-lived processes may not see it.
- Claude Code documents corporate proxy/custom CA behavior and can be identified locally by the signing identifier `com.anthropic.claude-code`.
- Codex CLI launches a Node shim but network traffic is produced by the signed native `codex` binary in the installed package on this Mac. Observatory also has a Codex-specific additive CA path via `CODEX_CA_CERTIFICATE`, which current Codex docs describe as the custom-CA override for HTTPS, login, and secure WebSocket clients.
- Gemini CLI is a Node script. It should be a 0.3 candidate only when the source process can be attributed to `gemini` and the Node process has current `NODE_EXTRA_CA_CERTS`.
- OpenCode/Hatch exposed the important class of bug: a persistent runtime can be stale even when direct tools work. It should be reported clearly; it should not be required for the launch promise.
- Python/Requests, Java, rustls/webpki, Electron apps, VS Code extensions, and custom wrappers vary widely in trust-store behavior. They are not safe to full-capture by default.

## 0.3 Support Matrix

| Runtime | Default 0.3 state | Full capture condition | Bypass condition |
| --- | --- | --- | --- |
| Claude Code | Supported | Source signing id is `com.anthropic.claude-code` and process env contains current `NODE_EXTRA_CA_CERTS` | Env missing/stale, source unknown |
| Codex CLI | Supported | Source signing id is `codex` and process env contains current `CODEX_CA_CERTIFICATE` | Env missing/stale, source unknown |
| Gemini CLI | Candidate | Source process is Node, command line identifies Gemini CLI, and env contains current `NODE_EXTRA_CA_CERTS` | Cannot attribute to Gemini or env missing/stale |
| OpenCode/Hatch | Diagnostic / metadata-only for launch | Only after separate live trust proof | Persistent server missing/stale trust, source ambiguous |
| Aider / Python tools | Metadata-only | Future: generated combined Requests/certifi bundle plus live proof | Default |
| VS Code/Electron extensions | Metadata-only | Future: app-specific proof | Default |
| Unknown/custom tools | Metadata-only/pass-through | Never by default | Always |

## Capture Policy

The policy runs before local TLS termination.

1. NetworkExtension handles only outbound TCP `:443`, then peeks SNI.
2. Non-provider or unreadable SNI is direct-relayed.
3. Provider SNI is relayed to the Go daemon with source metadata headers.
4. The daemon decides:
   - `inspect`: reply `200 CONNECT`, present Observatory leaf cert, parse and forward the HTTP request.
   - `tunnel`: reply `200 CONNECT`, open an opaque upstream tunnel, and never present an Observatory cert.
5. The daemon chooses `inspect` only when provider host and source trust readiness both match the support matrix.
6. The installed/stable daemon also requires the v0.3 transparent source marker.
   If an older extension or malformed relay reaches it without source metadata,
   it tunnels and records a bypass. The explicit `agents run` dev path keeps its
   old inspect behavior because it owns the child process and CA trust.
7. Client TLS failure still trips the existing capture pause circuit breaker.

This preserves the NetworkExtension low-blast-radius pivot while adding a second gate: provider host is necessary but not sufficient for full capture.

## Diagnostics

`agents doctor wire` should answer:

- Is the CA installed and trusted?
- Which supported clients are installed?
- Which running supported processes have current trust env?
- Which running supported processes are stale and will be bypassed?
- Which provider flows were recently tunneled because the source was unknown or stale?
- Which WebSocket paths are captured via HTTP fallback versus opaque pass-through?

The app should display the same state in plain language.

Runtime surfaces:

- `/healthz` includes capture pause state, TLS trust failures, and recent bypass summary.
- `/api/stream` emits both `capture` and `bypass` events. A bypass event is metadata only: provider host, runtime/provider family, source signing id, timestamp, and reason.
- `/api/coverage` returns aggregate capture/bypass counts plus recent redacted bypass metadata for release QA and support.

## Testing Plan

### Go Unit And Integration Tests

- Provider + supported source + current env -> TLS-inspected and captured.
- Provider + unknown source -> opaque tunnel, request succeeds, zero captures.
- Provider + supported source + stale env -> opaque tunnel, request succeeds, zero captures.
- Provider + supported source + stale env -> bypass event records stale trust reason.
- macOS PID/env parsing preserves `NODE_EXTRA_CA_CERTS` and
  `CODEX_CA_CERTIFICATE` when available; missing env evidence is not considered
  trust-ready.
- Stable installed daemon + missing transparent metadata -> opaque tunnel,
  request succeeds, zero captures.
- Non-provider host -> opaque tunnel, request succeeds, zero captures.
- Client rejects Observatory CA despite policy -> pause marker written and future flows bypass.
- Codex `/responses` WebSocket -> `426` fallback path remains covered.
- Non-Codex WebSocket -> opaque relay.
- Install QA confirms no global proxy vars and no root-replacing CA vars.

### Swift Tests

- SNI allowlist remains identical to Go provider host policy.
- Source metadata header builder includes transparent-flow marker, signing id, audit-token-derived PID when available, and sanitized values.
- Live feed decodes both capture and bypass events.
- Capture pause gate still short-circuits before proxy relay.

### Live Release QA

- `make v03-safe-capture-qa` starts a temporary monitor/proxy/CA, performs one supported-source OpenAI provider request with current `CODEX_CA_CERTIFICATE`, performs one unknown-source OpenAI provider request without trusting Observatory CA, and asserts `/api/coverage` records both a capture and a bypass. It uses intentionally invalid auth and accepts the provider 4xx response, so no API key is required.
- Fresh Claude Code request completes and captures.
- Fresh Codex request completes and captures.
- Fresh Gemini CLI request either captures with proof or is explicitly demoted before release.
- A local Python/Requests provider-shaped request without Observatory CA trust completes by opaque tunnel and produces zero captures.
- The same negative test appears as a bypass in `/api/coverage` and the live feed.
- A stale Hatch/OpenCode server is reported as stale and does not break provider traffic.
- `example.com` and local/private traffic remain untouched.

## Release Gates

0.3 is not shippable unless:

- Unknown provider-bound clients are pass-through by default.
- At least Claude Code and Codex pass live full-capture proof.
- Every supported runtime has a stale-trust bypass test.
- README/onboarding no longer implies universal body capture.
- Release QA includes a custom-tool negative test.
