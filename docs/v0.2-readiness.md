## Readiness Gates

### Gate A — Release Artifacts

Done when:

- `git status` has no accidental release-script/doc drift except intentional
  changes.
- `make release` completes without opening Finder or stealing GUI focus.
- `make release-layout-qa` passes on the fresh `dist/` artifacts.
- `NOTARY_PROFILE=<profile> make notarize` completes, or `make notarize`
  completes with App Store Connect API key env vars.
- `make release-qa` passes, proving both app and DMG are accepted by Gatekeeper
  and have stapled notary tickets.
- `dist/SHA256SUMS` matches the notarized final artifacts.

Evidence to capture:

```bash
make release
make release-layout-qa
NOTARY_PROFILE=<profile> make notarize
# or:
APP_STORE_CONNECT_KEY_ID=<key-id> \
APP_STORE_CONNECT_API_KEY_P8=/path/to/AuthKey_<key-id>.p8 \
APP_STORE_CONNECT_ISSUER_ID=<issuer-uuid> \
make notarize
make release-qa
make v02-readiness
spctl -a -vvv "dist/Agent Observatory.app"
spctl -a -vvv -t open --context context:primary-signature dist/Agent-Observatory-0.2.0-macOS.dmg
xcrun stapler validate "dist/Agent Observatory.app"
xcrun stapler validate dist/Agent-Observatory-0.2.0-macOS.dmg
cat dist/SHA256SUMS
```

### Gate B — Clean Local NE State

Done when:

- stale Observatory system-extension versions are gone, or a newer current build
  is activated/enabled and any older tombstone is explicitly documented as
  non-routing host residue;

- `agents trust status` reports that the current local CA is trusted in the

## v0.2 Epics

### Epic 1 — Non-Disruptive Release Pipeline

Goal: release commands never steal GUI focus and never imply public readiness
before notarization.

Shipped:

- `make release` is headless by default.
- `make release-polished` is the explicit Finder-layout path.
- `make release-layout-qa` is the local structural gate.
- `make release-qa` is strict public notarization/Gatekeeper QA.
- `scripts/notarize-release.sh` notarizes and staples app then DMG, refreshes
  zip/checksums, and runs strict QA.
- `scripts/v02-finalize.sh` groups the final interactive gates behind explicit
  opt-in flags for keychain trust, notarization, and release publication.

Remaining:

- Decide whether v0.2 ships the plain headless DMG or intentionally runs the
  polished Finder-layout path once at the end.

### Epic 2 — NE Install Reliability

Goal: a fresh user can enable/disable capture without becoming stuck in version
churn, stale CA trust, or extension approval ambiguity.

Remaining:

- Reboot or otherwise clear old Observatory system-extension versions waiting to
  uninstall.
- Reinstall the current `/Applications` app from fresh `dist/`.
- Run install/enable/disable twice and record status before/after.
- Follow `docs/ne-reset-runbook.md` for the exact cleanup/proof sequence.
- Re-run `scripts/v02-finalize.sh --trust` only if a future install mints a new
  local CA and `agents trust status` turns red again.

### Epic 3 — Flagship Runtime Proof

Goal: Claude Code is proven the same way Codex is proven: a real agent run
captures and completes under the shipped NE path.

Remaining:

- Use a newly launched shell/Claude Code process after install so trust vars are
  inherited.
- Capture one minimal turn in the live feed.
- Confirm the turn completes normally.
- Record the exact event JSON and completion evidence in
  `docs/launch-readiness.md`.

### Epic 4 — Release Publication

Goal: the public repo/release matches the actual product.

Remaining:

- Push final commits.
- Ensure CI green on the public badge branch.
- Publish the staged `v0.2.0` draft from the final commit.
- Update release title/notes and HN copy to match the Developer ID/notarized
  reality.

### Epic 5 — v0.2 Product Polish

Goal: preserve the inspector/debugger thesis while removing the obvious next
round of skepticism.

Recommended before broad launch:

- Add `SECURITY.md` covering local CA, prompt-body handling, uninstall, and
  reporting.
- Add a public release publication runbook and draft release notes.
- Add a short demo clip or at least one updated screenshot from the final build.
- Document coarse session-to-capture correlation honestly as a v0.2 limitation.
- Decide whether to keep Dock icon + menu bar or move to `LSUIElement` later.

## Product Vision

Agent Observatory is not just a packet-capture toy. The durable product is an
**agent context observability plane**:

- **Expected**: what repo/user/skill/tool context should be present.
- **Observed**: what local transcripts prove the agent runtime assembled.
- **Verified**: what the outbound provider request actually carried.
- **Explained**: where mismatches came from and what surface owns the fix.

v0.2 should stay focused on trust: make the invisible context stack inspectable
without breaking the machine. The next product step after v0.2 is not "capture
more bytes"; it is turning verified evidence into a control loop: canonical
context management, runtime-specific compatibility checks, and warnings before
an agent starts with missing or stale context.

## Explicit Non-Goals For v0.2

- Hosted/team observability.
- Raw prompt body persistence by default.
- HTTP/2 upstream replay.
- Per-request perfect session correlation.
- Antigravity opaque `.pb` decoding.
- App Store distribution.

## Definition Of Done

v0.2-ready means all four gates above are green with pasted evidence, final
artifacts are published from the final commit, and the README/release note make
no claim that is stronger than the verified behavior.
