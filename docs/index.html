Why it exists

Context is invisible

When an agent ignores a repo rule, you usually cannot tell whether the instruction was missing, buried, or overridden.

Tools drift quietly

Observatory compares expected tools and skills against transcript evidence and verified outbound requests.

Local evidence matters

The app runs on your Mac, reads local transcripts, and stores derived facts instead of raw prompt bodies on disk.

How the capture model works

  1. Open the app and inspect the demo feed without installing anything privileged.
  2. Choose live capture when you want to inspect your own agents.
  3. Approve the macOS NetworkExtension and login-keychain CA trust.
  4. Restart the agent shell so Claude Code or Codex inherits additive trust.
  5. Use agents normally and watch provider requests appear in the live feed.

Only allowlisted LLM-provider TLS flows are routed to the local proxy. Non-provider traffic is direct-relayed after the SNI check and is not decrypted or persisted.

What it shows

Expected context

Resolved repo instructions, skills, and tool expectations for the workspace.

Observed evidence

Facts read from local Claude, Codex, and agent transcript files.

Verified requests

Endpoint, runtime, prompt size, and tool names captured from outbound provider requests.

Launch status

The v0.2 line is signed, notarized, and passing local release QA. The remaining public-launch gate is a final real Claude Code completion proof on the launch machine before publishing the GitHub release.

Current limitations: macOS 26 preview app, HTTP/3 is not captured, ECH fails open, already-running agents need a restart, and session-to-capture correlation is coarse.

Agent Observatory is open source and local-first. Built for people who want a debugger for agent context, not another hosted trace warehouse.
